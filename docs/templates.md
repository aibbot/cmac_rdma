# C++ 模板与 Concepts 规范

> 适用范围：模板库、泛型算法、concepts、CRTP、策略类和编译期多态。

## 核心原则

代码首先必须正确、可维护、可诊断；性能与简洁性只能在不破坏所有权、边界、错误和生命周期的前提下追求。

## 规范规则

- MUST 仅在类型参数带来真实复用或性能收益时使用模板。
- MUST 用 concept、requires 或静态断言约束类型要求并改善错误信息。
- MUST 将模板实现放在可见位置或提供明确显式实例化策略。
- MUST 控制公共模板对 ABI、编译时间、依赖和代码体积的影响。
- SHOULD 用普通重载或小型接口替代仅支持少数固定类型的泛型设计。
- MUST NOT 用 SFINAE、宏或深层 traits 隐藏简单的业务分支。
- MUST 为 forwarding reference、perfect forwarding 和引用折叠设计正确的生命周期语义。
- MUST 防止模板把数组退化、错误移动、意外转换或悬垂视图传播到下游。
- SHOULD 为可扩展算法定义最小概念，而不是要求完整容器类型。
- MUST 对模板的异常、noexcept、并发和 allocators 行为进行文档化。
- MUST 为关键类型、错误类型、边界类型和编译失败路径提供编译测试。
- MUST NOT 在模板中直接依赖未隔离的平台寄存器或系统 API。

## 常见失败模式

- 仅让成功路径看起来正确，却没有定义错误、取消、关闭或资源回收。
- 把隐式转换、默认值、全局状态或未记录的时序当作接口契约。
- 以风格、性能或短期方便为理由削弱可测试性和可观测性。

## 验证清单

- [ ] concept/约束准确表达所需操作而非过宽类型。
- [ ] 实例化不会引入循环依赖或不可控代码体积。
- [ ] 转发和存储不会延长临时对象的错误生命周期。
- [ ] 公共错误信息对消费者可读。
- [ ] 关键实例化组合在目标编译器上构建通过。
