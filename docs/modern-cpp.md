# Modern C++20 规范

> 适用范围：用户态 C++20 服务、库、工具和高性能数据路径。

## 核心原则

代码首先必须正确、可维护、可诊断；性能与简洁性只能在不破坏所有权、边界、错误和生命周期的前提下追求。

## 规范规则

- MUST 使用项目锁定的 C++20 标准与 clang-format 配置；局部约定优先于通用风格。
- MUST 用值语义、RAII、enum class、constexpr、span、optional 和强类型表达真实语义。
- MUST NOT 在公共头文件使用 using namespace 或依赖传递包含。
- MUST 让所有权、可空性、单位、范围、同步性和错误通道在类型或接口中可见。
- SHOULD 优先组合而非继承；继承只用于稳定的可替换契约。
- MUST 将构造完成后的不变量、移动后的状态与关闭后的状态定义清楚。
- MUST NOT 让单参数构造函数产生意外隐式转换；默认使用 explicit。
- MUST 对外部长度、偏移、计数、整数转换和容器索引进行边界/溢出检查。
- SHOULD 使用 [[nodiscard]] 标记不能安全忽略的结果。
- MUST NOT 用宏替代可用的语言机制，或用 bool 承载多于两种业务状态。
- MUST 将平台、ABI、寄存器和协议细节隔离在适配层，不向业务层泄漏。
- SHOULD 让函数名称暴露副作用、阻塞、资源转移和状态改变。
- MUST 遵循 [naming.md](naming.md) 的标识符、单位、锁状态和兼容边界约定。

## 常见失败模式

- 仅让成功路径看起来正确，却没有定义错误、取消、关闭或资源回收。
- 把隐式转换、默认值、全局状态或未记录的时序当作接口契约。
- 以风格、性能或短期方便为理由削弱可测试性和可观测性。

## 验证清单

- [ ] 头文件独立包含后能够编译。
- [ ] 公共函数的参数和返回值能表达借用、转移、可空与错误。
- [ ] 构造、移动、析构和 Close/Stop 路径没有资源泄漏。
- [ ] 新增 enum 在 switch 中不会被 default 静默吞掉。
- [ ] 格式、编译警告和相关静态分析通过。
