# constexpr 与编译期计算规范

> 适用范围：常量、查找表、寄存器字段、单位转换、配置验证与编译期算法。

## 核心原则

代码首先必须正确、可维护、可诊断；性能与简洁性只能在不破坏所有权、边界、错误和生命周期的前提下追求。

## 规范规则

- SHOULD 用 constexpr 表达无副作用、可验证且稳定的常量和纯计算。
- MUST 让编译期常量保留单位、范围、端序或位字段语义，不能只留下裸字面量。
- MUST NOT 以 constexpr 掩盖依赖运行时硬件版本、环境、时间或用户配置的值。
- MUST 使用命名掩码、范围和 helper 表达寄存器字段，避免散落位移魔数。
- SHOULD 用 consteval 仅在必须禁止运行时调用且诊断更有价值时使用。
- MUST 控制大 constexpr 表、递归和模板计算对编译时间和二进制的影响。
- MUST 让 constexpr 函数与运行时等价路径保持相同边界、溢出和错误语义。
- MUST NOT 在编译期静默截断地址、长度、频率或数组大小。
- SHOULD 用 static_assert 验证协议大小、对齐、查找表边界和不变量。
- MUST 将目标相关常量集中在平台层，不向通用业务层泄漏。
- MUST 对 constexpr 结果的 signed/unsigned 转换、位宽和溢出有明确规则。
- SHOULD 通过单元测试和 static_assert 双重验证重要计算。

## 常见失败模式

- 仅让成功路径看起来正确，却没有定义错误、取消、关闭或资源回收。
- 把隐式转换、默认值、全局状态或未记录的时序当作接口契约。
- 以风格、性能或短期方便为理由削弱可测试性和可观测性。

## 验证清单

- [ ] 常量有名称、单位和来源。
- [ ] static_assert 覆盖关键边界和值域。
- [ ] 编译期表不会导致不可接受的编译/二进制成本。
- [ ] 运行时输入没有被错误地当作常量。
- [ ] 平台特定定义与数据手册/ABI 一致。
