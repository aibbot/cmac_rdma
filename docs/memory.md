# C++ 内存与所有权规范

> 适用范围：内存、句柄、mmap、DMA buffer、文件描述符、线程、回调和异步对象。

## 核心原则

代码首先必须正确、可维护、可诊断；性能与简洁性只能在不破坏所有权、边界、错误和生命周期的前提下追求。

## 规范规则

- MUST 为每个资源指定唯一拥有者、借用者、释放者和关闭顺序。
- MUST 优先用 RAII 包装内存、FD、socket、mmap、线程、锁和设备句柄。
- MUST 使用 unique_ptr 表达独占所有权；shared_ptr 仅用于真实独立共享生命周期。
- MUST NOT 用 shared_ptr 修复不清楚的对象关系或让循环引用长期存在。
- MUST 保证 span、string_view、引用、iterator 和裸指针不跨越底层存储生命周期。
- MUST 处理分配失败、部分初始化、异常、取消和重复关闭。
- SHOULD 使用按值返回，避免为“节省拷贝”返回悬垂引用。
- MUST 对外部输入计算的大小、乘法和偏移检查溢出。
- MUST NOT 将虚拟地址、物理地址、DMA 地址和 mmap 地址混为一谈。
- SHOULD 把大 buffer 的复用绑定到可观察租约或序列号，而不是隐式约定。
- MUST 在异步任务保存对象前复制、移动或延长其真正所有权。
- MUST 明确析构是否会阻塞、是否需要先 Stop、以及失败如何被诊断。

## 常见失败模式

- 仅让成功路径看起来正确，却没有定义错误、取消、关闭或资源回收。
- 把隐式转换、默认值、全局状态或未记录的时序当作接口契约。
- 以风格、性能或短期方便为理由削弱可测试性和可观测性。

## 验证清单

- [ ] 所有早返回和错误路径都释放或转移资源。
- [ ] 异步回调不能在对象销毁后访问成员。
- [ ] 缓存/池化对象不会在 DMA 或其他线程使用时被复用。
- [ ] Sanitizer、泄漏检查或等价资源审查覆盖新增路径。
- [ ] 地址/长度/对齐与外部 ABI 或硬件约束一致。
